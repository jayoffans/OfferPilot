# S1-3 中文工作台设计与前端约定

### S3-2 中文岗位匹配追加

延用既有 Token、侧栏、表单、Notice、badge 和响应式布局，在职位详情增加“岗位匹配”区域。顶部三态建议和版本状态，中间按学历与届别、技能、项目及实习、工作条件、个人偏好分组，逐条 details 展开画像字段、正式条目 ID、JD 引文/行号/字符位置、规则版本与核实问题；底部提供修改画像、审核 JD、重新计算及既有收藏。所有状态有文字，不展示分数或投递假按钮。

无正式画像或无当前已审核条件时禁用计算并引导补充；请求中防重，失败保留已有结果并提示核实状态；旧结果明确标为历史，提示“匹配依据已变更”。未审核和旧版条件单独列出未参与原因。历史仅展示最近结果，不用旧结果替换当前判断。用户切换时取消旧请求。

“我的资料”新增独立偏好表单，可只补城市、方向、类型、薪资和实习可用时间，不重填履历。偏好与硬性资格分开；日/月/年与税费口径不明时提示核实。偏好保存使用同一画像 revision，原有未保存导航保护继续适用。真实 Chromium 在 1440/768/390px 检查无横向溢出，截图仅含合成资料，见 S3-2 验收。

S1-3 提供账户与 PDF 文件管理；S2-1 在同一设计系统扩展“我的资料”；S2-2A 增加隔离 Mock 测试任务与可追溯候选。S2-2B 提供本地 BYOK 和独立授权，后续单份真实合成样本验收不代表总体质量达标，生产仍关闭。S3-1 增加私有职位、JD 规则整理和人工审核；匹配及投递管理后续，不创建虚假指标。

| `/resumes/[id]` | 改名、原件下载、确认删除、查询清理状态 | 元数据和生命周期分别请求；隐藏/失败文件仍可凭此 URL 查询并重试删除 |
| `/profile` | 分组编辑教育、技能、项目、实习/工作；确认/修订/拒绝候选 | 全量保存检查 revision；正式与候选分开；可部分保存、查看逐字段来源；409 保留输入，重新载入前提醒丢弃修改 |
| `/jobs` | 查询、搜索、筛选和分页已保存职位 | 查询来自服务端本人列表；按工作类型、收藏和审核状态筛选，按更新/创建/名称排序 |
| `/jobs/new` | 粘贴 JD → 基本信息 → 条件审核并保存 | 只需岗位名称，可手工录入；规则整理是独立免费操作；允许保留待审核条件并部分保存 |
| `/jobs/[id]` | 查看原文与历史快照、审核条件、编辑、收藏、删除 | 所有修改使用 revision；JD 更新使旧条件失效；409 保留输入并只读核对最新内容 |

桌面为 224px 侧栏与账户顶栏；800px 以下改为顶部品牌、账户菜单及四个直接导航入口。主内容最大宽度 1320px，移动端保留 18px 边距。列表移动端将状态放到第二行，文件名截断但详情显示完整名称。

## 交互规范

- 认证由 FastAPI 的 HttpOnly、SameSite Cookie 管理。浏览器不读 Cookie，不把用户凭据写入 localStorage/sessionStorage；CSRF 仅内存保留，刷新后从真实接口恢复。
- 上传需明确选择文件并点击提交。进度来自 XHR 实际传输事件；100% 仅表示请求已发送，保存和文本解析须等 201。超时、网络中断或未知结果要求先检查列表；有 Location 时直接查询服务器生命周期。
- 改名和删除使用 Radix Dialog；改名打开聚焦输入，关闭恢复原按钮。删除确认优先保留文件，不因 503 提示已删除；完成 204 后显示已删除生命周期记录与返回列表入口。
- 普通列表 API 只返回 active+parsed；不虚构“处理中”文件。处理中的详情最多自动查询 10 次，每次间隔 2 秒，之后用户手动刷新；离开页面终止请求和计时器。
- 401 返回登录；404 统一不可访问说明；409 要求刷新/核查；429 不自动重试；503 提供真实状态和清理恢复。下载 blob 在使用后撤销引用。
- 文件名始终以 React 文本渲染，不使用 `dangerouslySetInnerHTML`。SQLite 无时区日期按 UTC 解析，以 Asia/Shanghai 展示。

## 组件与依赖

S2-1 的 `profile-page/profile-editor/profile-candidates` 复用现有 Token、Notice、Radix 弹窗及工作台 Shell。桌面编辑/说明分列，小屏单列；来源使用可展开细节，逐字段显示用户填写、简历支持或来源已删除。完成提示只列分组和缺失字段，不制造分数。候选不可靠引用标明未获支持；已修订旧引文只作参考。

表单可存部分内容，空字段为 null；空条目、时间反向、进行中却填结束时间、毕业类型无月份先提示。保存/审核期间禁重复提交；409 保留输入并禁止覆盖，可只读查看服务器最新内容。确认和修订是独立用户动作，修订需勾选本人核实；无依据/否定候选原值确认按钮不可用。

页面导航/退出及刷新有未保存提示；Next 同文档历史返回没有可靠全局取消 API，采用本标签页纯内存草稿恢复：按真实 user.id 保存四组业务 Input 和原基线 revision，每次访问仍 GET 真实 API，新版冲突不能因再次返回而解除。保存、明确放弃和会话变化清除；不缓存候选/来源/凭据，不写 localStorage/sessionStorage。浏览器关闭或硬刷新后只有服务器已保存资料会恢复；未保存提示是必要边界，不承诺持久草稿自动保存。

### S2-2A 隔离 Mock 测试界面

默认简历详情不显示抽取按钮。只有服务端 `OFFERPILOT_MOCK_EXTRACTION_UI=true` 才呈现明确标为“Mock 简历抽取测试”的面板；后端还须独立开启 development Mock 配置，UI 开关不赋予后端调用权限。面板创建、取消和有限重试使用真实身份、CSRF、简历版本、幂等请求键和任务 revision；状态从持久接口读取，最多自动查询 20 次、间隔 1 秒，离开页面终止请求。真实 DeepSeek 未启用，也没有 Key 收集入口。

候选仍由原 S2-1 页面审核，Mock 候选和审核记录显式标为测试结果；用户确认后正式条目的来源继续标明 Mock。可展开查看 V2 原始字段、技术栈、职责与成果、经历归属、服务端页段/字符位置以及待核实原因。confidence 只作为模型输出元数据，文字定位不等于语义或真实性核验。缺证据、否定、学习计划与归属风险继续由后端阻止原值确认，用户可按真实情况修订或拒绝。

验证使用临时 SQLite、固定合成中文 PDF 和无网络 Mock Provider；loopback 私密控制仅存在于 E2E launcher，不加入正式应用/OpenAPI/前端代理。新增真实浏览器场景覆盖全链审核、排队取消、失败重试和运行中取消/删除的迟到结果；保留 S1/S2-1 回归。1440/768/390 状态截图验证无水平溢出。正式默认隐藏入口有组件级断言；浏览器全链运行在显式 Mock UI 模式。结果不证明真实模型质量、生产容量或其他浏览器兼容性。

`src/app` 负责路由、元数据、中文根布局和安全代理入口；`src/components` 负责账户、导航、上传、列表与详情；`src/lib` 负责生成类型、API/CSRF、认证上下文与代理。UI 无数据库访问与业务授权逻辑，后端仍是唯一权威。

### S2-2B 中文真实解析入口

“我的资料”追加局部AiResumePanel，复用panel/Notice/Radix/设计Token。Key密码输入即发送清空、会话reset清临时状态；配置/免费预览/主动勾选收费提交分开。预览可完整滚动核对、显示外传风险/脱敏残留/模型/最多一次与token/账单不确定性；无Key或后端关闭时禁用。不会轮询POST，状态读取有70次上限及手动刷新，Key失效有重新配置入口。

成功只提示pending并由用户载入候选；画像dirty、候选编辑或冲突时禁覆盖。原S2-1四类逐项确认/编辑/拒绝不变；source显示DeepSeek/model/run或Mock测试及手工来源。刷新/重新登录恢复持久任务和候选，但Key不恢复。没有总分或不可信准确率。

新增十个组件测试与两个免费Provider注入Chromium场景，沿用真实API/临时0006库；无网络调用DeepSeek，不能用截图或通过数证明真实模型质量。1440/768/390授权窗口查看后修宽度/链接换行；手机有可滚动内容，无横向溢出。详见 [S2-2B验收](../docs/S2-2B-acceptance.md)。

### S3-1 中文职位管理

职位沿用 Shell、Token、Notice、Radix Dialog、面板、表单和来源证据样式，没有新增依赖。列表显示岗位、公司、地点、薪资、类型、收藏、审核进度和更新时间；空账户与筛选无结果有不同引导。搜索有短时防抖，页面离开取消请求；代理只允许职位列表既定且不重复的查询参数。

新建分三步，用户粘贴 JD 后仅需填写岗位名称，其余未知信息可留空；没有 JD 时可手工建立全部条件。免费确定性规则须明确点击，界面说明无大模型调用、覆盖有限、结果全部待审核。每条条件可修改类型、内容、必须/优先/待核实分类、原文引文和位置，修改后重新标为待审核；确认是独立用户动作。重新规则整理前说明会替换本次编辑条件及审核进度，保存之前不更新数据库。

审核区域在宽屏与招聘原文并列，小屏单列；详情按硬性、优先、待核实分组展示文字证据、JD 版本、行和字符位置，并可展开历史快照。字符位置按 Unicode 字符计数；重复引文不默认猜测首个位置，可由用户指定起点。过期要求保留旧版本引文，只作核对参考，需明确重新绑定当前 JD 才能再次确认。未审核条件不能作为后续可信匹配依据，不显示匹配分数。

编辑、收藏和删除遵循当前 revision，409 保留本地输入并阻止覆盖，可只读查询最新内容，明确放弃后重载。创建请求禁重复点击，同一未确认结果保留幂等键。导航、刷新和退出有未保存提示；临时编辑只按用户及职位保存在本标签页内存，会话变化清除，不进入浏览器持久化存储。已保存的原文、快照和审核进度从后端恢复，手工编辑不会改动正式画像。

JD 和所有用户字段以 React 文本渲染。招聘链接仅展示经服务端验证的 HTTP(S) 链接，并在浏览器再次拒绝危险 Scheme 与嵌入凭据；新窗口使用 noopener/noreferrer 与 no-referrer，不自动访问招聘网站。正式 API 仍负责身份、对象授权、CSRF、Schema、版本和证据校验。
