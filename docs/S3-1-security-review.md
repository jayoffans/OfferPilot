## 2. 授权、并发及重放

- 正式 jobs 路由统一依赖现有 `get_current_user`。所有变更共用服务端 Cookie 会话、Origin 与 CSRF 检查；客户端 `user_id` 被显式 Schema 拒绝。
- 职位查询、更新 CAS 与删除在 SQL 中限定当前用户。跨用户与不存在资源返回一致的 404；条件 ID 只能取自本人当前职位，不能跨职位或跨用户写入。
- 独立探针覆盖详情/条件查询、职位更新/删除/收藏、整组条件保存、单条条件新增/修改/删除及审核：跨用户 404，匿名 401，各写操作缺 CSRF 403。伪造其他用户条件 ID 后职位 revision 与内容不变。
- 变更先领取职位 revision，再在同一事务更新子资源；错误回滚，过期版本不能静默覆盖。条件确认使用同一职位版本边界。
- 创建回执以当前用户与幂等键唯一约束保护请求；同键异内容拒绝。删除职位后回执 `job_id` 置空，保存最小请求摘要，重复旧创建请求返回 409，不能复活已删职位。独立探针验证删除重放后本人职位为零，另一用户职位仍保留。
- 请求摘要与岗位内容摘要分开：前者核对同一幂等键的完整请求，后者按基本信息与 JD 防止重复导入。既有职位的已审核条件不会被新的导入请求静默替换；等价自动解析/预览输入复用已有资源，冲突条件拒绝。
- 真实退出与重登录后保存的职位可恢复；职位流程不读取或修改正式画像，独立探针中正式画像 revision 始终为 0。

## 3. 条件、证据与不可信 JD

- 首版规则只提出原文片段，候选默认 pending；不会调用模型、浏览器、URL fetch 或执行 JD 指令。`JDParser` 是可替换解析契约，不代表已接入真实 AI。
- `熟悉 Java 优先` 保持 preferred；`计算机相关专业` 保持原范围并标 uncertain。用户可修订内容、分类、来源和审核状态，确认动作不会把 uncertain 自动改成 must。
- 引文位置由服务端对选定职位 JD 快照逐字验证；重复引文无明确起点时拒绝猜测；跨职位快照不能作为可信来源。独立探针重算 `jd_text[source_start:source_end] == evidence_text`，全部通过。
- JD 变更追加快照并增加版本，旧条件保持原快照绑定，统一 pending/stale。旧来源直接确认返回 409；把旧引文绑定新 JD 而引文不存在时返回 422，职位 revision 不变。
- 恶意指令只作为不可信文本；注入形态候选保持待核实和待审核。HTML/脚本通过 React 文本显示，未发现 `dangerouslySetInnerHTML` 或 JD 执行工具接线。
- 招聘链接只保存与展示。后端拒绝非 HTTP(S) Scheme、凭据、非标准端口、环回/内网/链路本地/元数据主机及模糊 IP 写法；前端另有协议守卫与外链隔离。没有按用户 URL 发起服务端请求。
- 原始 JSON 孤立 surrogate 经当前 Pydantic 原生 Unicode 校验返回脱敏 422；验证错误不回显正文。引擎继续使用 `hide_parameters=True`，新服务没有正文日志。

规则整理仍是保守词法提示，不能证明任意招聘文本的语义正确。用户审核只确认自己接受的条件，不把缺失信息变为负面事实；S3-2 仍需版本化可信条件筛选与匹配金标准。

## 4. 发现并修复的问题

独立迁移测试实际复现：原证据 CHECK 在非空引文但缺一个或两个坐标时返回 SQL UNKNOWN，数据库会接受该记录。已在 ORM 和本轮新迁移中加入 `source_start IS NOT NULL`、`source_end IS NOT NULL`；缺坐标、部分坐标、无引文却有坐标、负起点和空区间均自动拒绝。修复后新迁移 8 项及全迁移 40 项通过。

审查另外提出超长未拆分片段可能导致解析 Schema 错误；规则现跳过超过 2000 字符的单段并给出人工补充提示，JD 原文完整保留。具体语义反例与最终业务测试由本轮职位测试覆盖。

## 5. 迁移兼容性与数据生命周期

`0007` 只追加 `saved_jobs`、`job_jd_snapshots`、`job_requirements`、`job_create_receipts` 四表，历史 `0001`～`0006` 不改。迁移专项把旧 0006 的全部业务表逐行快照与升级后对照，包括正式画像 revision、待审核候选、原文证据、提取运行关联及合成授权/计量历史；全部保持原值，不自动创建职位或确认旧候选。

验证包含 ORM/迁移 CHECK、外键、索引、唯一约束一致；外键检查为空；职位删除级联移除快照与条件，回执仅留下空职位引用，其他职位及 S1/S2 表不变。空新表可安全降级至 0006 并重升；存在职位数据或仅剩创建回执时拒绝有损降级；offline 降级不能跳过在线安全检查。

岗位正文、快照及条件只用于用户保存、审核和后续证据匹配，随职位删除清理。创建回执用于防止旧请求复活，未保存 JD/联系方式；完整账户导出、注销及回执保留/删除期限仍沿用项目上线前待落实项。数据库硬删除不等于 SQLite 空闲页、磁盘或备份安全擦除。

## 6. 未覆盖项与 S3-2 前置条件

- 此处仅验证 SQLite；PostgreSQL 实际运行、生产容量与备份恢复没有执行。
- 不把确定性规则的合成回归结果描述为真实模型质量或通用 JD 理解能力。
- S3-2 需要只消费当前 JD 版本、已审核且语义适用的条件；无证据/未知/待核实与“明确不满足”必须分开，人工无引文条件保留用户提供来源。
- 匹配结果需绑定正式画像 revision、JD/条件版本、Schema/解析/规则版本并可复算；相关专业范围、校招届别、混合必须/优先及否定条件仍须独立标注与反例验证。
- S3-1 没有匹配分数、推荐、自动申请或 Browser 能力；本轮结束后停止。
