最终审查首轮离线检查覆盖 **全部本地 refs 可达的 14 个提交、556 个提交历史文件 blob**、提交消息，以及当时 Git 允许加入的 **350 个工作树文件**。另外读取 **10 个非 commit 的 Codex checkpoint tree refs**，补查仅存在于这些快照的 **97 个 blob**；去重合计 **653 个 blob**。历史包含本地开发分支与已存在的远程跟踪 refs；这比仅扫描 HEAD 或 `git diff` 更广。对于 Git 忽略文件，只记录敏感类别的文件名；另外在本机核对两份环境文件是否含非空秘密设置，未输出其值。以上数量对应本轮新增整理提交之前的复核快照；提交后复跑的具体数量应以本机脱敏报告及 [最终发布清单](GITHUB-RELEASE-CHECKLIST.md) 为准。

这些 checkpoint refs 的对象类型为 tree，`git rev-list --all` 不会将其作为提交历史遍历，原扫描范围说明因此补充明确，脚本增加独立遍历。**普通的指定功能分支 push 仅发送该分支的可达提交/对象，不会自动推送这些 `refs/codex/` 引用**；不要用 mirror 或打包整个 `.git` 代替发布分支。它们本次亦经过检查，但没有改写或删除。

在上述范围内，**没有发现可确认的真实 API Key、私钥、数据库口令或真实求职者资料误提交**。这是规则扫描与人工核对的有限结论，不是“仓库不可能有秘密”的保证。唯一历史二进制文件为明确的合成评测 PDF，见下文。

尚有两个公开前决定：**Git 作者邮箱是否允许公开**，以及 **PyMuPDF 与项目自身的许可方案**。后者见 [第三方许可审查](THIRD_PARTY_LICENSES.md)，此轮未代替权利人添加项目 `LICENSE`。

## 可复跑扫描

仓库根目录执行（Windows）：

```powershell
& .\backend\.venv\Scripts\python.exe -B scripts/security_scan.py `
  --output frontend/artifacts/security/release-history-scan.json
```

macOS/Linux 在依赖安装后可用 `backend/.venv/bin/python`；脚本本身只依赖 Python 3.11 标准库与 Git。输出只含**路径、类别、行号、blob 和示例提交标识**，不输出匹配值、源代码行、Cookie 或环境文件内容；报告目录被 Git 忽略。退出成功只表示扫描完成，候选仍需人工核对，不作为自动“安全放行”条件。

实现遍历 `git rev-list --all` 与各提交的完整 tree，并逐一解析 refs，额外读取非 commit 的 tree/blob refs；按 blob 去重，再用 `git cat-file --batch` 读取内容，同时扫描提交消息。报告 Schema 为 v2，区分 `history`、`non_commit_ref` 与 `worktree`，只存在于非 commit refs 的 blob 单列数量。工作树使用 `git ls-files --cached --others --exclude-standard`，不会把忽略文件的内容读取到报告中。不会联网、调用模型、执行被扫描文本、改变 refs 或推送。

首轮扫描发现 74 个候选记录（工作树与多个历史版本会重复计算），类别是连接串 12、字面口令模式 53、手机号模式 9；均核对为上表所述合成/占位/插值/属性/URL 数字。后续加入演示脚本或文档会改变工作树候选数，因此应检查报告位置，而不是把该数字作为零风险阈值。

作品集整理阶段新增 Windows/macOS/Linux 用户目录形态检查后，曾得到 **14 个提交、556 个唯一 blob、85 条候选**，其中 11 条是历史用户目录记录。本次最终复核再纳入非 commit refs 后，去重共 **653 个 blob、98 条候选记录**：连接串 13、字面口令模式 62、手机号模式 9、用户目录模式 14。其中额外 13 条来自 checkpoint：连接串 1、字面口令 9、用户目录 3，均核对为示例、插值、合成测试或普通开发路径；不是已确认泄漏的凭据。当前工作树仍无用户目录模式命中，正文非示例邮箱、长 Provider Token 和私钥标记均无命中。这里“条”按文件版本/类别记录计数，不是秘密数量，同一文件的多个版本会重复记录。

二进制人工审阅共 13 条，是历史/当前同一合成 PDF 加 11 张新演示 PNG，没有新增未审阅的二进制文件；非 UTF-8 历史 blob 仅该合成 PDF。最终首轮脱敏报告为 `frontend/artifacts/security/release-history-scan.json`；媒体哈希、PNG 元数据及本机配置非空检查结果位于同目录 `media-and-env-review.json`。这些报告均被既有 `frontend/artifacts/` 规则忽略，不纳入公开提交。

额外在系统临时目录建立两个提交的合成仓库，验证：已删除文件中的历史假 Key 仍被发现、独立 tree ref 和直接 blob ref 中的假 Key 也被发现、当前工作树不误报已删除文件、忽略的 `.env` 只出现名称、二进制被标为人工复核、序列化报告不含测试 Key 值。**7 项全部通过**；临时仓库已随上下文退出清理，没有修改项目历史。脱敏验证结果位于同目录 `scanner-self-check.json`。

- `docs/images/demo/` 用于审阅后的合成截图，**没有被忽略**。

已用 `git check-ignore` 验证本地环境、数据库、演示状态、日志、ZIP、私钥及普通 PDF 被忽略；合成 PDF 与演示截图路径允许跟踪。`.gitignore` 不会移除已跟踪文件，所以历史检查仍然必要。

## 若以后发现历史敏感内容

1. 立即停止计划中的公开/推送；先撤销或轮换相关凭据，确认使用范围和可能已存在的克隆/缓存。
2. 记录类别、受影响路径/提交/refs、暴露时段与影响，不在 Issue 或日志复述秘密值。真实个人资料应另行确认删除和通知责任。
3. 在隔离副本制定 `git filter-repo` 等清理方案，列出要移除的 blob、受影响 refs 和协作者重新克隆步骤；经所有者批准才执行历史重写、远程删除或强制推送。
4. 重新扫描清理后的全部计划发布 refs；考虑 GitHub 缓存、fork、旧 clone 和备份副本。仅删当前文件或再提交一次不足以消除历史暴露。

本次没有发现需要立即撤销的已提交凭据，也没有运行上述历史清理操作。

## 审查的实际限制

该脚本不是完整 DLP、熵扫描、恶意代码分析或依赖漏洞扫描器；没有 OCR，不读取压缩包/加密数据中的内容，不保证识别任意姓名、地址、身份证或混淆后的秘密。PDF 与截图必须结合生成来源和人工可视审阅。没有读取远程独有、尚未存在于本机 refs 的对象，也没有扫描 reflog/不可达对象、操作系统临时目录、第三方备份或外部模型存储；这些通常不随普通分支推送，但如计划发布其他 refs 或完整 `.git` 归档，须重新扩大审查。

项目仍保留会话 BYOK、CSRF、对象归属、证据审核、幂等/租约围栏、私有文件与导出/注销边界。此次定位调整没有使真实个人数据外传获得默认授权，也没有把未来的公开服务安全要求宣称为已实现。
