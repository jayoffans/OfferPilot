# OfferPilot 产品需求文档（PRD）

**版本：** 0.5（S2-2A 合成 Mock 抽取与可信审核）
**日期：** 2026-10-12
**状态：** 邀请制试点方向已确认；能力是否实现以代码和验收结果为准

> 首批面向中国大陆计算机/软件方向大学生、应届毕业生及初级求职者，采用邀请制和会话 BYOK。大陆部署及供应商数据策略仍需验证。S1 提供账户/私有 PDF，S2-1 提供手工画像及候选审核，S2-2A 接通合成样本 Mock 持久抽取，验收见 [PLAN](PLAN.md) 和 [本批记录](S2-2A-acceptance.md)。上传本身只解析文本，测试任务须主动创建；默认不开放抽取按钮。真实 DeepSeek、付费调用、BYOK、岗位匹配、Browser Agent、完整账户导出/注销、云存储及生产 Worker 未启用，不能据此宣称完整 MVP 已完成。

## 1. 产品概述

OfferPilot 是面向大学生的 AI 求职 Agent。它把简历中的事实整理成可确认的个人求职画像，帮助学生发现和理解岗位、评估匹配度、针对岗位改进简历，并管理申请进度。对于重复填写的网申字段，OfferPilot 可在用户监督下辅助填写。

**产品原则：AI 处理重复劳动，用户掌握关键决策。** OfferPilot 不自动海投，不替用户决定申请，不代替用户提交申请，也不伪造经历或技能。

## 2. 用户与需求

### 主要用户

- 正在准备实习或校招的在校大学生、应届毕业生；首批聚焦计算机/软件方向。
- 同时关注多个岗位，需要把简历经历与职位要求对应起来的求职者。
- 对招聘网站表单重复填写、截止日期和申请进度管理感到负担的求职者。

### 用户要完成的任务

1. 快速建立准确、可编辑的求职资料，不必重复整理简历内容。
2. 看懂岗位的硬性条件、核心要求、工作内容和截止时间。
3. 知道匹配判断依据、个人优势和具体缺口，而不是只看一个分数。
4. 获得有证据、不夸大经历的简历修改建议。
5. 在一个地方查看申请状态和下一步事件；主动通知在首发后验证。
6. 后续在受支持、允许自动化的网站上复用已确认资料辅助网申，最终提交始终由用户亲自操作。

## 3. 产品目标与衡量方式

### 目标

- 缩短从上传简历到得到可行动岗位建议的时间。
- 提高学生理解岗位要求和准备材料的效率。
- 降低重复录入和遗忘申请进度的情况。
- 让 AI 输出可追溯、可纠正、可撤销。

### MVP 指标（试点假设，需在试点后校准）

| 指标 | 定义 | 初始目标 |
|---|---|---:|
| 画像确认完成率 | 上传简历的用户中完成必要字段确认的比例 | ≥70% |
| 岗位分析可用率 | 用户对岗位解析结果选择“基本正确/可用”的比例 | ≥80% |
| 匹配解释有帮助率 | 用户认为优势、缺口与建议有帮助的比例 | ≥75% |
| 建议证据覆盖率 | 每项关键建议能指向画像事实或 JD 原文的比例 | 100% |
| 投递记录完整率 | 用户开始记录的申请中具备状态和下一步信息的比例 | ≥80% |
| 未授权提交数 | 未经用户主动操作而产生的正式申请提交 | 0 |

上述数值为待试点校准的质量目标，不是当前成绩或已经验证的上线容量。后续通知与 Browser Agent 启用后再纳入其可用率指标。

**护栏指标：** 未经确认写入画像的高风险事实、错误推荐导致的关键条件误判、越权访问用户资料、未授权申请提交均应为 0；解析失败需可观测并向用户说明，后续提醒和浏览器辅助亦遵循此要求。

## 4. 核心用户流程

1. 受邀用户注册/登录；目标方向、地点、实习/全职偏好可稍后填写，避免首次进入就要求完成冗长问卷。
2. 上传有可选中文本的 PDF；系统校验文件并提供可恢复的处理状态。模型能力需用户按已批准配置提供会话 BYOK 并明确发起；未提供密钥时可手动录入。
3. 系统展示候选字段、原文证据和确认状态；用户修改、确认或拒绝后形成画像。模型自报置信度不等于事实正确概率，不触发自动确认。
4. 用户粘贴 JD 或手动录入职位；可保存来源链接，首发不自动访问或抓取链接。
5. 系统提取结构化 JD；用户可校正职位、地点、必须/优先条件和截止时间，未知内容保持未知。
6. 匹配引擎依据已确认事实、明确条件和偏好生成四态判定与证据解释；用户保存、忽略或标记“准备投递”。
7. 用户手动更新投递状态，记录备注、笔试/面试和下一步日期；工作台优先展示今日、逾期和近期行动。

首发完整闭环止于“保存职位并管理投递状态”。定向简历建议、主动提醒和 Browser Agent 属于后续场景，不作为 MVP 验收前置。

## 5. 功能需求与优先级

### P0：MVP 必须具备

#### 5.1 账户、隐私与资料

- 用户只能查看和修改自己的资料、简历、岗位和申请；后续提醒同样隔离。
- 支持上传文本型 PDF；显示解析状态、失败原因、重新处理和删除入口。DOCX 和扫描件 OCR 后置。
- 从简历抽取匹配所需的教育、技能、项目、实习/工作经历；每项保存来源、证据片段和置信度。学历、专业、毕业时间等硬条件需有结构化且经用户确认的事实。姓名及联系方式不是匹配前置，最小必要数据发送方案在 AI 接入前验证。
- 用户确认前，候选字段标记为“待确认”，不得静默成为已确认事实。
- S2-2A 只在明确的隔离 Mock 模式验证合成简历，任务与候选、确认后的来源均显示测试身份；未登记样本失败，不能用固定假值包装真实用户资料。任务状态持久保存，可查询、取消和按剩余额度有限重试；取消/删除/版本变化后的迟到结果不得写回。真实模型另行授权及验收。
- 用户能修改、确认、拒绝候选字段；修改后保留当前值及必要的来源记录。
- S2-1 正式画像按教育、技能、项目、实习/工作分组，可只填部分字段并保存；空字段保持未知。学校、学历、专业、年月及预计/实际毕业语义分别记录；进行中的经历与未知结束时间不同，不推算经历年限。完成提示只列已填写分组及缺失信息，不显示综合评分。
- 手工值显示“用户填写”，审核值显示确认/修订与来源证据；原文引用不代表系统核验真实性。待确认、已确认、已修改、已拒绝候选均与正式条目分开。缺证据、否定或学习计划候选不能直接确认原值，用户可明确修订或拒绝。
- 保存、审核及删除来源材料均更新画像 revision；并发编辑返回冲突，保留本地输入供核对，不静默覆盖。未保存离开或退出需提醒；刷新、重登录恢复已保存资料。
- 删除简历清除相关候选与原文证据；用户已确认/自行提供的正式值保留，来源显示“来源简历已删除”。需同时删除这些值时由用户在“我的资料”编辑删除，不误删独立手工经历。
- 支持导出与删除账户数据；删除时同时安排删除原始文件及其派生数据。
- 模型费用由用户通过会话 BYOK 承担；密钥不写入数据库、日志、分析事件或浏览器持久化存储，不以开发者密钥自动回退。会话失效后任务暂停，具体实现与供应商数据处理配置在 AI 批次验证。

#### 5.2 岗位导入和 JD 分析

- 支持粘贴 JD、手动录入和记录来源链接；链接仅保存，不触发服务器抓取。经许可的公开 API、官方 feed 或公开页面连接器属于后续能力。
- 每条岗位保存来源、用户提供的原始内容快照、录入时间与规范化字段；首发岗位记录按用户私有，不建立未经授权的共享岗位库。
- 提取职位名称、公司、地点、职能、经验/学历条件、技能、职责、语言要求、截止时间；未明确的信息标记未知，不推测为事实。
- 允许用户校正解析结果；岗位来源与来源时间在详情中可见。
- MVP 不包含未经许可的大规模抓取，不尝试绕过登录、付费墙、验证码或反自动化措施。

#### 5.3 匹配与推荐

- 对用户确认的画像与已解析岗位计算匹配结果，分解为硬性条件、技能、经历证据、偏好等维度。
- 展示推荐理由、优势、缺口、未知项、投递价值建议，并为每条理由提供证据来源。
- 区分“明确满足”“部分满足”“未发现证据”“明确不满足”；简历没写到不等于用户没有该能力。
- 结果是辅助决策，不使用单一分数自动筛除岗位；用户可查看规则与修改偏好。
- 首发不显示 0–100 总分；硬性资格、技能/经历证据和个人偏好分别展示，综合提示由版本化确定性规则产生。LLM 不能决定分数、修改规则判定或替用户决定投递。
- 用户可标记有帮助/不准确、忽略、收藏或开始准备申请。

#### 5.4 申请跟踪与工作台

- 支持用户建立申请记录并管理状态：准备中、已提交、笔试、面试、Offer、拒绝、撤回、已关闭。
- 支持记录提交日期、岗位链接、下一步日期和备注；后续多版本管理加入使用版本的明确关联。
- 支持笔试、面试、截止日期等手动事件；工作台列出今日、逾期和近期行动，不承诺后台通知推送。
- 状态变更保留时间线，允许用户修正，不强制线性流程。“等待回复”作为已提交状态的展示含义，收藏不等于已经投递，收到 Offer 不等于接受 Offer。

### P1：MVP 后续迭代

#### 5.5 简历优化建议

- 按岗位生成建议，覆盖经历排序、表达清晰度、关键词对应和缺失证据提示。
- 建议必须引用原简历内容及 JD 依据；不增加未被用户提供或确认的事实、数字、技能、职责或成果。
- 提供建议文本供用户编辑复制；不直接覆盖原始简历。

#### 5.6 主动提醒

- 用户配置提醒时间、渠道和频率；初始可先验证应用内提醒，再评估邮件/日历同步。
- 提醒任务可幂等重试，保留发送结果；允许用户暂停提醒，失败可观测。

#### 5.7 受监督的 Browser Agent 辅助填写

- 仅针对用户主动选择的岗位和受支持、允许自动化访问的网站启动。
- 用户自行打开或登录企业页面；登录密码、验证码和 MFA 由用户处理，不由系统收集或保存。
- 系统把已确认资料映射到识别出的表单字段，显示字段来源；不确定字段留空并询问用户。
- 每页填写后提供检查机会；检测到页面结构变化、提交按钮、声明/授权、敏感问题或不确定映射时暂停并交还用户。
- 只填写，不点击最终提交，不签署声明，不代表用户接受条款或作出事实陈述。
- 不绕过验证码、MFA、访问控制、反自动化机制或站点策略；连接器采用白名单和速率限制。
- 用户可随时停止、清除会话并查看辅助步骤记录。

#### 5.8 其他候选能力

- DOCX、OCR 和更丰富的简历格式支持。
- 更多经过审核的招聘来源连接器、站点专用表单适配器。
- 邮件/日历提醒集成、团队/学校职业中心协作。
- 多版本简历管理、建议差异对比、PDF 导出。
- 用户授权下的邮件解析与申请状态辅助更新。
- 面试准备、岗位优先级规划和求职复盘。

### 暂不做

- 自动海投、无人值守批量申请、替用户提交申请或接受 Offer。
- 简历内容造假、自动回答无法由资料证实的经历或合规问题。
- 未经许可抓取登录后、受限或付费内容；验证码/MFA/反机器人规避。
- 对雇主或学生进行自动化筛选、排名或录用决策。
- 保证录用、薪资或投递成功率。

## 6. 质量与非功能要求

- **安全与隐私：** 简历及个人信息按敏感个人数据处理；传输加密、存储加密、最小权限、租户隔离、审计访问；生产日志不得记录完整简历、联系方式或认证凭据。
- **可靠性：** 长任务异步执行；重复任务具备幂等键；解析、AI、抓取和提醒失败可重试并显示明确状态。
- **可解释性：** 推荐、字段抽取和建议记录模型/提示模板版本、引用证据、时间及用户修订记录。
- **性能目标（试点假设，待测量）：** 普通页面交互 P95 < 2 秒；简历解析与岗位分析提供异步状态，不承诺固定完成时间；超时后允许重试。具体容量及模型时延在真实部署和授权评测后确定。
- **可访问性：** 键盘可操作、语义化表单、错误说明清楚；匹配信息不只用颜色表达。
- **可观测性：** 记录脱敏后的任务状态、耗时、失败类别、模型调用成本和质量反馈。
- **可移植性：** 业务层不绑定单一模型厂商；模型调用通过适配层封装。

## 7. MVP 验收标准

1. 受邀新用户可登录、上传一份文本 PDF，并在证据帮助下确认或修改解析字段；无模型密钥或模型不可用时可手动完成资料录入。
2. 用户可粘贴 JD 或手动录入，并查看可编辑的结构化结果；可保存来源链接但不自动抓取。
3. 匹配页能分别展示理由、优势、缺口、未知项和投递建议，且重要结论有来源证据。
4. 用户能保存职位，手动记录申请进展、时间事件、备注与下一步，刷新或重登录后保留结果。
5. 工作台显示真实的今日、逾期和近期行动；空状态给出可执行的下一步，不使用假数据冒充结果。
6. 用户可以导出并删除个人数据；账户之间的数据访问相互隔离。删除覆盖原件、派生数据和相关任务，备份保留限制向用户说明。
7. 未提供有效会话 BYOK 不调用付费模型，不回退使用开发者 API Key；所有重要 AI 输出通过版本化 Schema 和证据校验。

定向简历建议、主动提醒与 Browser Agent 按后续独立验收标准发布，不阻挡上述闭环的邀请制试点。
