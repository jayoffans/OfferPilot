# OfferPilot 产品需求文档（PRD）

**版本：** 0.1（项目启动稿）  
**日期：** 2026-09-25  
**状态：** 待产品与工程团队评审

## 1. 产品概述

OfferPilot 是面向大学生的 AI 求职 Agent。它把简历中的事实整理成可确认的个人求职画像，帮助学生发现和理解岗位、评估匹配度、针对岗位改进简历，并管理申请进度。对于重复填写的网申字段，OfferPilot 可在用户监督下辅助填写。

**产品原则：AI 处理重复劳动，用户掌握关键决策。** OfferPilot 不自动海投，不替用户决定申请，不代替用户提交申请，也不伪造经历或技能。

## 2. 用户与需求

### 主要用户

- 正在准备实习或校招的在校大学生、应届毕业生。
- 同时关注多个岗位，需要把简历经历与职位要求对应起来的求职者。
- 对招聘网站表单重复填写、截止日期和申请进度管理感到负担的求职者。

### 用户要完成的任务

1. 快速建立准确、可编辑的求职资料，不必重复整理简历内容。
2. 看懂岗位的硬性条件、核心要求、工作内容和截止时间。
3. 知道匹配判断依据、个人优势和具体缺口，而不是只看一个分数。
4. 获得有证据、不夸大经历的简历修改建议。
5. 复用已经确认的个人信息填写网申，并保留提交前的人工检查。
6. 在一个地方查看申请状态、下一步事件和提醒。

## 3. 产品目标与衡量方式

### 目标

- 缩短从上传简历到得到可行动岗位建议的时间。
- 提高学生理解岗位要求和准备材料的效率。
- 降低重复录入和遗忘申请进度的情况。
- 让 AI 输出可追溯、可纠正、可撤销。

### MVP 指标（试点假设，需在试点后校准）

| 指标 | 定义 | 初始目标 |
|---|---|---:|
| 画像确认完成率 | 上传简历的用户中完成必要字段确认的比例 | ≥70% |
| 岗位分析可用率 | 用户对岗位解析结果选择“基本正确/可用”的比例 | ≥80% |
| 匹配解释有帮助率 | 用户认为优势、缺口与建议有帮助的比例 | ≥75% |
| 建议证据覆盖率 | 每项关键建议能指向画像事实或 JD 原文的比例 | 100% |
| 投递记录完整率 | 用户开始记录的申请中具备状态和下一步信息的比例 | ≥80% |
| 未授权提交数 | 未经用户主动操作而产生的正式申请提交 | 0 |

**护栏指标：** 未经确认写入画像的高风险事实、错误推荐导致的关键条件误判、越权访问用户资料、未授权申请提交均应为 0；解析失败、提醒漏发、浏览器辅助失败需可观测并向用户说明。

## 4. 核心用户流程

1. 用户注册并说明目标方向、地点、实习/全职偏好等可选条件。
2. 上传 PDF 或 DOCX 简历；系统校验文件，提取文本并解析为候选字段。
3. 系统展示字段、原文证据和置信度；用户修改或确认后形成当前画像。
4. 用户通过允许的岗位来源、粘贴 JD 或输入岗位链接添加职位。
5. 系统提取结构化 JD；用户可校正职位、地点、要求和截止时间。
6. 匹配引擎依据必需条件、偏好和可验证经历生成解释；用户保存、忽略或标记“准备申请”。
7. 用户选择岗位后查看针对性简历建议；每条建议展示对应的 JD 要求和用户经历依据，用户自行采纳和编辑。
8. 用户可为申请生成网申资料草稿，并在受支持的网站上启动浏览器辅助。用户自行登录，逐页检查填入内容；最终提交由用户亲自操作。
9. 用户更新申请状态，或记录笔试、面试等事件；系统按用户设置提醒。

## 5. 功能需求与优先级

### P0：MVP 必须具备

#### 5.1 账户、隐私与资料

- 用户只能查看和修改自己的资料、简历、岗位、申请与提醒。
- 支持上传 PDF/DOCX；显示解析状态、失败原因、重新处理和删除入口。
- 从简历抽取联系信息、教育、技能、项目、实习/工作经历；每项保存来源、证据片段和置信度。
- 用户确认前，候选字段标记为“待确认”，不得静默成为已确认事实。
- 用户能修改、确认、拒绝候选字段；修改后保留当前值及必要的来源记录。
- 支持导出与删除账户数据；删除时同时安排删除原始文件及其派生数据。

#### 5.2 岗位采集和 JD 分析

- 支持粘贴 JD、添加岗位链接、手动录入；可接入经许可的公开 API、官方 feed 或公开页面连接器。
- 每条岗位保存来源、原始内容快照、抓取/录入时间与规范化字段。
- 提取职位名称、公司、地点、职能、经验/学历条件、技能、职责、语言要求、截止时间；未明确的信息标记未知，不推测为事实。
- 允许用户校正解析结果；岗位来源与来源时间在详情中可见。
- MVP 不包含未经许可的大规模抓取，不尝试绕过登录、付费墙、验证码或反自动化措施。

#### 5.3 匹配与推荐

- 对用户确认的画像与已解析岗位计算匹配结果，分解为硬性条件、技能、经历证据、偏好等维度。
- 展示推荐理由、优势、缺口、未知项、投递价值建议，并为每条理由提供证据来源。
- 区分“明确满足”“部分满足”“未发现证据”“明确不满足”；简历没写到不等于用户没有该能力。
- 结果是辅助决策，不使用单一分数自动筛除岗位；用户可查看规则与修改偏好。
- 用户可标记有帮助/不准确、忽略、收藏或开始准备申请。

#### 5.4 简历优化建议

- 按岗位生成建议，覆盖经历排序、表达清晰度、关键词对应和缺失证据提示。
- 建议必须引用原简历内容及 JD 依据；不增加未被用户提供或确认的事实、数字、技能、职责或成果。
- 提供建议文本供用户编辑复制；MVP 不直接覆盖原始简历。

#### 5.5 申请跟踪与提醒

- 支持用户建立申请记录并管理状态：准备中、已提交、笔试、面试、Offer、拒绝、撤回、已关闭。
- 支持记录提交日期、岗位链接、使用的简历版本、下一步日期和备注。
- 支持笔试、面试、截止日期等事件与用户配置的提醒时间。
- 提醒任务可重试，保留发送结果；MVP 至少支持应用内提醒。邮件/日历同步列为后续能力。

#### 5.6 受监督的 Browser Agent 辅助填写

- 仅针对用户主动选择的岗位和受支持、允许自动化访问的网站启动。
- 用户自行打开或登录企业页面；登录密码、验证码和 MFA 由用户处理，不由系统收集或保存。
- 系统把已确认资料映射到识别出的表单字段，显示字段来源；不确定字段留空并询问用户。
- 每页填写后提供检查机会；检测到页面结构变化、提交按钮、声明/授权、敏感问题或不确定映射时暂停并交还用户。
- 只填写，不点击最终提交，不签署声明，不代表用户接受条款或作出事实陈述。
- 不绕过验证码、MFA、访问控制、反自动化机制或站点策略；连接器采用白名单和速率限制。
- 用户可随时停止、清除会话并查看辅助步骤记录。

### P1：MVP 后续迭代

- 更多经过审核的招聘来源连接器、站点专用表单适配器。
- 邮件/日历提醒集成、团队/学校职业中心协作。
- 多版本简历管理、建议差异对比、PDF 导出。
- 用户授权下的邮件解析与申请状态辅助更新。
- 面试准备、岗位优先级规划和求职复盘。

### 暂不做

- 自动海投、无人值守批量申请、替用户提交申请或接受 Offer。
- 简历内容造假、自动回答无法由资料证实的经历或合规问题。
- 未经许可抓取登录后、受限或付费内容；验证码/MFA/反机器人规避。
- 对雇主或学生进行自动化筛选、排名或录用决策。
- 保证录用、薪资或投递成功率。

## 6. 质量与非功能要求

- **安全与隐私：** 简历及个人信息按敏感个人数据处理；传输加密、存储加密、最小权限、租户隔离、审计访问；生产日志不得记录完整简历、联系方式或认证凭据。
- **可靠性：** 长任务异步执行；重复任务具备幂等键；解析、AI、抓取和提醒失败可重试并显示明确状态。
- **可解释性：** 推荐、字段抽取和建议记录模型/提示模板版本、引用证据、时间及用户修订记录。
- **性能目标（试点）：** 普通页面交互 P95 < 2 秒；简历解析与岗位分析提供异步状态，不承诺固定完成时间；超时后允许重试。
- **可访问性：** 键盘可操作、语义化表单、错误说明清楚；匹配信息不只用颜色表达。
- **可观测性：** 记录脱敏后的任务状态、耗时、失败类别、模型调用成本和质量反馈。
- **可移植性：** 业务层不绑定单一模型厂商；模型调用通过适配层封装。

## 7. MVP 验收标准

1. 新用户可上传一份支持格式的简历，并在证据帮助下确认或修改解析字段。
2. 用户可粘贴 JD 或添加岗位链接并查看可编辑的结构化结果。
3. 匹配页能分别展示理由、优势、缺口、未知项和投递建议，且重要结论有来源证据。
4. 用户能获得不捏造事实的定向简历建议，并选择性采纳到自己的文档。
5. 用户可记录申请进展和时间事件，并收到设置好的应用内提醒。
6. 对支持的网申页面，用户可看到自动填入的字段及来源；流程在最终提交之前停止。
7. 用户可以导出并删除个人数据；账户之间的数据访问相互隔离。
